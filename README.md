# แบบประเมินความเสี่ยงงานยกเคลื่อนย้ายจากคลิปวิดีโอ

แอป Streamlit ของกลุ่ม G13 รายวิชา CP413705 AI Workshop III (วิทยาลัยการคอมพิวเตอร์ มหาวิทยาลัยขอนแก่น)
อัปโหลดคลิปงานยก แล้วระบบกรอก **แบบประเมินความเสี่ยงงานยกเคลื่อนย้าย (Lifting Handling Risk Assessment)** ให้ครบ 7 ขั้นตอน
โดยวัดตำแหน่งมือ มุมบิดตัว และจำนวนรอบยกจาก keypoint ของ MediaPipe Pose (ไม่ต้องเทรนโมเดล)

## สิ่งที่แอปทำ

| ขั้นตอนในแบบประเมิน | ที่มาของค่า |
|---|---|
| 1. น้ำหนักวัตถุ | ผู้ใช้กรอก |
| 2. ตำแหน่งมือขณะยกและวาง → น้ำหนักจากตาราง 4×3 | ระบบวัดความสูงมือ (V) และระยะยื่น (H) ตอนหยิบและตอนวาง แล้วใช้ค่าที่น้อยกว่า |
| 3. ตัวคูณความถี่ | ระบบนับรอบยกในคลิปแล้วคิดเป็นรอบ/นาที · ผู้ใช้เลือกชั่วโมงทำงานต่อวัน และเลือกแถวความถี่เองได้ |
| 4. ตัวคูณบิดลำตัว (0.85 หรือ 1.0) | มุมบิดสูงสุดระหว่างหยิบถึงวาง เทียบเกณฑ์ 45° |
| 5. RWL | ขั้นตอนที่ 2 × 3 × 4 |
| 6. LH Index | น้ำหนักวัตถุ ÷ RWL × 100 |
| 7. ระดับความเสี่ยง 1–4 | จาก LH Index |

หน้าจอมี 3 แท็บ

- **ผลประเมิน** แบบประเมินครบ 7 ขั้นตอน พร้อมแถบสีระดับความเสี่ยง และปุ่มดาวน์โหลดผลเป็น CSV
- **วิดีโอผลลัพธ์** คลิปที่วาดโครงกระดูก ตารางน้ำหนัก และตัวนับรอบ (กดปุ่มสร้างเมื่อต้องการ)
- **รายรอบและกราฟ** ตารางผลของแต่ละรอบยก กราฟความสูงมือ ระยะยื่น และมุมบิดตามเวลา

ถ้าคลิปมีหลายรอบยก แอปประเมินทุกรอบ แล้วสรุปด้วยรอบที่มีค่า RWL ต่ำที่สุด

## รันบนเครื่องตัวเอง

```bash

.venv\Scripts\activate            # macOS/Linux: source .venv/bin/activate
pip install -r requirements.txt
streamlit run streamlit_app.py
```

ตรวจตัวเลขของตารางความถี่ RWL และขอบระดับความเสี่ยง:

```bash
python lifting.py
```

## วิธีถ่ายคลิป

1. ตั้งกล้องนิ่ง เห็นผู้ยกเต็มตัวตั้งแต่หัวถึงเท้าตลอดคลิป
2. ผู้ยกยืนตรง มือแนบลำตัว นิ่ง 2 วินาทีก่อนเริ่ม ระบบใช้ช่วงนี้วัดสัดส่วนร่างกาย
3. หลังวางของทุกครั้ง ปล่อยมือกลับมาแนบลำตัวก่อนยกรอบถัดไป ระบบใช้ท่านี้แบ่งรอบ
4. ถ่ายด้านข้างของผู้ยกจะวัดระยะยื่นมือได้ใกล้จริงที่สุด
5. กรอกส่วนสูงจริงของผู้ยกในแอป

## การคำนวณ

ขั้นตอนต่อเฟรมเหมือน notebook ต้นฉบับ: อ่านเฟรม → สกัด keypoint → ลดการสั่นด้วย Kalman filter → ปรับเทียบ ซม./พิกเซล
จากส่วนสูง → หาพิกัด 3 มิติด้วย `cv2.solvePnP` → มุมหันเทียบกล้อง → มุมบิดตัว → ตำแหน่งมือ (H, V) → ช่องในตารางน้ำหนัก

**นับรอบยก (`detect_lifts`)** หนึ่งรอบคือหนึ่งช่วงที่มือออกจากท่ายืนพักแล้วกลับมาพัก โดยมือเคลื่อนในแนวดิ่งอย่างน้อย 20 ซม.
ในช่วงนั้นจุดที่มือต่ำสุดกับสูงสุดคือจังหวะหยิบและจังหวะวาง จุดไหนมาก่อนคือจังหวะหยิบ จึงใช้ได้ทั้งงานยกขึ้นและงานยกลง

### ส่วนที่ต่างจาก notebook ของกลุ่ม

สูตรปรับเทียบ มุมหัน มุมบิด ตำแหน่งมือ ตารางน้ำหนัก และระยะเอื้อม คัดลอกมาโดยไม่แก้ ส่วนที่เปลี่ยนมีดังนี้

| ส่วน | notebook | แอป | เหตุผล |
|---|---|---|---|
| ค่าปรับได้ | ตัวแปร global | `Params` ส่งเข้าฟังก์ชัน | ให้ slider ส่งค่าเข้ามาได้ |
| เกณฑ์บิดตัว | 20° (กลุ่มปรับ) | 45° เป็นค่าเริ่มต้น ปรับได้ | แบบประเมินกำหนด 45° |
| ตัวนับรอบ | `LiftCounter` นับจังหวะมือขึ้น ≥ 35 ซม. | `detect_lifts` แบ่งรอบด้วยท่าพัก | ของเดิมพลาดงานยกลงและงานยกระยะสั้น และให้เวลาหยิบเท่ากับเวลาวาง |
| `solve_camera_pose` | ใช้คำตอบของ `solvePnP` ทันที | ทิ้งคำตอบที่คนอยู่หลังกล้อง แล้วแก้ใหม่ | คลิป `ยกกลาง` ได้ความสูงมือ 205 ซม. ตลอด 30 วินาทีแรกเพราะคำตอบกระจกเงา |
| วิดีโอผลลัพธ์ | วาดที่ขนาดเต็ม | ย่อด้านยาวเหลือ 960 px ก่อนวาด และเก็บภาพตารางไว้ใช้ซ้ำ | เร็วขึ้นราว 5 เท่า |
| สรุปผล | เทียบน้ำหนักกับค่าตารางโดยตรง | ขั้นตอนที่ 3–7 ของแบบประเมิน | ให้ตรงแบบประเมิน |

ทดสอบกับคลิป 3 คลิปใน `clips/` (คลิปละ 5 รอบ สลับยกขึ้นและยกลง) เทียบกับเวลาใน `docs/clip_ground_truth.docx`
ใช้ค่าตั้งต้นทั้งหมด และสมมติส่วนสูง 170 ซม. เพราะไม่ได้บันทึกส่วนสูงจริงของผู้ยก

| คลิป | รอบจริง | notebook เดิม | แอป | รอบที่จังหวะหยิบและวางตรงกับเฉลย (คลาดไม่เกิน 1 วินาที) |

## ข้อจำกัด

- **ระยะยื่น H อ่านเกินจริง** กล้องตัวเดียวประมาณความลึกได้ไม่แม่น ท่ายืนพักยังอ่านได้ 20–30 ซม. คอลัมน์ของตารางจึงเอนไปทาง "ระยะเอื้อม" ซึ่งให้ผลประเมินเข้มกว่าจริง
- **มุมบิดอ่านต่ำกว่าจริง** รอบที่เฉลยระบุว่าบิดตัววัดได้สูงสุด 13–31° จึงไม่ถึงเกณฑ์ 45° ของแบบประเมิน ลดเกณฑ์ได้ที่ "ค่าปรับขั้นสูง"
- **ต้องกลับมายืนพักมือระหว่างรอบ** ถ้ายกต่อเนื่องโดยไม่ปล่อยมือ ระบบนับรวมเป็นรอบเดียว
- **ความถี่จากคลิปสั้น** คลิปที่ยกติดกัน 5 รอบใน 43 วินาทีคิดเป็น 7 รอบ/นาที ซึ่งอาจสูงกว่างานจริง ให้เลือกแถวความถี่เองในขั้นตอนที่ 3
- **ยังไม่ได้ทดสอบบน Streamlit Cloud** ทดสอบบน Windows กับ Python 3.11 เท่านั้น `packages.txt` เขียนตามที่ OpenCV บน Linux ต้องใช้
- คลิปที่อัปโหลดถูกเก็บเป็นไฟล์ชั่วคราวบนเครื่องที่รันแอป
